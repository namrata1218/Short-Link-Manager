# Full-Stack Intern Take-Home — Short Link Manager

**~5 hours of work. Submit within 3 days.**

Build an internal tool for a marketing team: they paste in long campaign URLs, get short
links back, and later check how those links performed. You'll build the API and a React UI.

## Example

| Destination URL | Options given | Resulting short link |
|---|---|---|
| `https://shop.example.com/collections/summer-2026/sale?utm_source=newsletter&utm_medium=email&utm_campaign=summer_sale_26` | none | `http://localhost:3000/r/k7Bx9q` |
| `https://blog.example.com/posts/how-we-cut-our-build-time-by-80-percent` | slug `build-time` | `http://localhost:3000/r/build-time` |
| `https://example.com/webinar/register?id=99321&ref=partner` | slug `webinar`, cap `500` | `http://localhost:3000/r/webinar` |

Visiting `http://localhost:3000/r/build-time` sends the visitor to the blog post and
logs a click. Once `/r/webinar` has served 500 clicks, it stops redirecting and returns
410 instead.

Host and port are whatever your app runs on — there's no domain to configure.

## What it does

1. **Create a link** — destination URL, optional custom slug, optional click cap.
2. **`GET /r/:slug`** — redirect to the destination and record the click (timestamp +
   referrer). If the cap is hit or the link is disabled, return **410 Gone** instead.
3. **List view** — search and pagination, both handled server-side. Show status and click count.
4. **Detail view** — clicks per day for the last 7 days.
5. **Disable or delete** a link.

No auth, no deployment — assume one trusted user, running locally.

## Stack

React (TypeScript preferred). Backend in Node or Python, framework your choice. Any
database.

## Decide these yourself

Left unspecified on purpose. Pick an answer, implement it, explain it in `DECISIONS.md`:

- A custom slug that's already taken
- Cap checked before or after the redirect — and what happens when two people click the
  last remaining click at the same moment
- Whether stats stay visible once a link is capped
- Timezone for "clicks per day"

## Optional bonus: one AI feature

Either slug suggestions generated from the destination page's title, or a plain-English
summary of the 7-day click data.

Free keys from [OpenRouter](https://openrouter.ai) (any `:free` model) or
[Google AI Studio](https://aistudio.google.com/apikey). The key stays server-side in an
env var, commit a `.env.example`, and **the app must work with no key set** — we'll run
it that way.

Skipping this costs you nothing.

## Submit

A **GitHub repo link**, containing:

- **`README.md`** — how to run it. Clone to working app in under 5 minutes.
- **`DECISIONS.md`** — your four answers above, one tradeoff you'd revisit with more time,
  anything unfinished, and how you used AI.
- **Optional:** a 3–5 minute screen recording walking through what you built. Unpolished
  is fine.

Push as you go rather than one commit at the end.

Unfinished and documented beats broken and unmentioned. Good luck.
